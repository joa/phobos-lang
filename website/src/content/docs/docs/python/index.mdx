The `phobos` package lets you write a kernel as a Python function and launch
it from Python. A function decorated with `@ph.kernel` is a Phobos kernel
spelled in Python. It has Phobos's semantics, not Python's: the package reads
the function's source and never runs it. Every Python construct the package
accepts spells one construct of the [language](/docs/reference/spec/), and
the Python side adds nothing to the language.

```python
from __future__ import annotations

import phobos.lang as ph


@ph.kernel
@ph.autotune(BLOCK=[16, 8192])
def saxpy(x: ph.tensor[ph.f32][N], y: ph.tensor[ph.f32][N], out: ph.tensor[ph.f32][N], alpha: ph.f32):
    base: ph.let = ph.ctx.block.x * BLOCK
    out[base:+BLOCK] = alpha * x[base:+BLOCK] + y[base:+BLOCK]


print(saxpy.source)
saxpy[lambda meta: (-(-meta["N"] // meta["BLOCK"]),)](x, y, out, 2.0)  # x, y, out: torch or CuPy arrays
```

This is [saxpy](/docs/examples/saxpy-fp32/), the same kernel as
`examples/saxpy_fp32.ph`, and `saxpy.source` prints the Phobos it spells:

```phobos
@autotune(BLOCK in [16, 8192])
kernel saxpy(x: tensor<f32>[N], y: tensor<f32>[N], out: tensor<f32>[N], alpha: f32) {
    let base = ctx.block.x * BLOCK
    out[base :+ BLOCK] = alpha * x[base :+ BLOCK] + y[base :+ BLOCK]
}
```

## How it works

1. **The front end** reads the module's source with Python's `ast`. It writes
   the Phobos program the kernel spells, with a span map from each construct
   back to the Python text it came from.
2. **`phobos-compile`** compiles that program to PTX for the card. It holds
   the span map, so every error, race report and trace location it prints
   names a line of the Python file. Beside the PTX it writes the kernel's
   launch contract: the parameter slots, the index width, the CTA size and
   the shared memory.
3. **The launcher** binds the arguments to the contract and launches the
   kernel through the CUDA driver, with `ctypes`. An argument is any array
   that offers `__cuda_array_interface__`, so torch, CuPy and Numba arrays all
   work, and no array library is needed to compile.
4. **The autotuner** searches the kernel's own `@autotune` space. It checks
   every variant against a reference and times the ones that pass.

Compiled kernels go in the same kernel cache the inference runtime uses, so
a kernel compiles once per chip.
